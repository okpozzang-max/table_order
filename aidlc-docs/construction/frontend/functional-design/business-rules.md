### Q11 추천 근거 (localStorage)
- 요구사항은 새로고침 시 세션 유지와 16시간 후 자동 로그아웃이다. 카운터 PC에서 영업 중 탭이나 브라우저가 닫혔다 다시 열려도 만료 전이면 재로그인이 필요 없어야 운영에 편하다. sessionStorage는 탭을 닫으면 로그아웃되어 이 점에서 불리하다.
- XSS에 노출되는 정도는 localStorage와 sessionStorage가 같다. 보안 이득이 크지 않다.
- 보완: 토큰과 함께 `expiresAt`을 저장하고, 만료 시각에 맞춰 자동 로그아웃(타이머 + 앱 시작 시 검사)한다. 로그아웃 시 즉시 삭제한다.

## 1. 입력 검증 규칙

공통: 문자열은 앞뒤 공백을 제거한 뒤 검사한다. 검증은 제출 시 수행하고, 필드를 벗어날 때(blur)에도 해당 필드를 검사한다. 오류는 해당 필드 아래에 표시하고 첫 오류 필드로 포커스를 이동한다. 서버의 `VALIDATION_ERROR.fields`도 같은 위치에 표시한다.

| 폼 | 필드 | 규칙 | 오류 문구 |
|---|---|---|---|
| 테이블 초기 설정 | 매장 식별자 | 필수, 1~50자 | 매장 식별자를 입력해주세요. |
| | 테이블 번호 | 필수, 1~999 정수 | 테이블 번호는 1~999 사이 숫자로 입력해주세요. |
| | 비밀번호 | 필수, 숫자 4자리 (`^\d{4}$`) | 비밀번호는 숫자 4자리입니다. |
| 관리자 로그인 | 매장 식별자 / 사용자명 / 비밀번호 | 모두 필수 | 해당 항목을 입력해주세요. |
| 테이블 등록 (관리자) | 테이블 번호 | 필수, 1~999 정수 | 테이블 번호는 1~999 사이 숫자로 입력해주세요. |
| | 비밀번호 | 필수, 숫자 4자리 | 비밀번호는 숫자 4자리입니다. |
| 메뉴 등록/수정 | 메뉴명 | 필수, 1~50자 | 메뉴명은 1~50자로 입력해주세요. |
| | 가격 | 필수, 정수, 100 이상 1,000,000 이하 | 가격은 100원~1,000,000원 사이 정수로 입력해주세요. |
| | 설명 | 선택, 0~300자 | 설명은 300자 이내로 입력해주세요. |
| | 카테고리 | 필수, 1~30자 (기존 카테고리는 자동완성 목록으로 제안) | 카테고리는 1~30자로 입력해주세요. |
| | 이미지 URL | 선택. 입력 시 `http://` 또는 `https://`로 시작하는 유효한 URL | 이미지 주소는 http 또는 https URL이어야 합니다. |
| 과거 내역 필터 | 시작일/종료일 | 둘 다 선택. 둘 다 있으면 시작일 <= 종료일 | 시작일이 종료일보다 늦을 수 없습니다. |

- 가격 입력은 숫자만 허용하고 소수/음수를 막는다. 표시용 천 단위 구분자는 입력 중이 아닌 blur 시 적용한다.
- 같은 규칙을 백엔드 Functional Design에서도 동일 값으로 사용한다 (프론트 검증은 UX용이며 서버가 최종 판단).

## 2. 장바구니 규칙

| 규칙 | 내용 |
|---|---|
| 담기 | 같은 `menuId`가 있으면 수량 +1, 없으면 수량 1로 추가 (G1) |
| 최대 수량 | 항목당 20. 20에서 담기/증가 시도 시 수량을 바꾸지 않고 "한 메뉴는 최대 20개까지 담을 수 있어요." 안내, 증가 버튼은 비활성화 |
| 감소 | 수량 1에서 감소하면 항목 제거 (G2) |
| 삭제 | 항목 삭제 버튼으로 즉시 제거 (확인 팝업 없음) |
| 비우기 | "비우기" 버튼. 항목이 있을 때만 활성. 확인 팝업 없이 비움 |
| 합계 | `sum(unitPrice * quantity)`를 변경 즉시 다시 계산. 원 단위 정수 |
| 가격 스냅샷 | `unitPrice`는 담는 시점의 메뉴 가격. 이후 메뉴가 바뀌어도 장바구니 값은 그대로이며, 주문 시 서버가 검증한다 |
| 영속화 | 변경될 때마다 localStorage 저장. 앱 시작 시 복원. `tableKey`가 다르면 버림 |
| 서버 전송 | 장바구니 편집 중에는 서버 호출 없음. 주문 확정 시에만 전송 |
| 주문하기 버튼 | 장바구니가 비어 있으면 비활성 |

## 3. 주문 확정 규칙 (US-C4.1, C4.2, E1, E2)

1. "주문하기" -> 주문 확인 모달: 항목(이름, 수량, 단가, 소계)과 총 금액 표시. "주문 확정" / "취소".
2. 확정 시 `clientOrderId`를 확인한다. `pendingOrder`에 같은 `cartSignature`가 있으면 그 ID를 재사용하고, 없으면 새 UUID를 만들어 저장한다.
3. `POST` 요청 중에는 "주문 확정" 버튼을 비활성화하고 로딩 표시한다 (이중 클릭 방지).
4. 성공: `pendingOrder` 삭제 -> 장바구니 비우기 -> `/customer/order-complete`로 이동 (주문 번호 전달). 완료 화면에서 5초 카운트다운 후 `/customer/menu`로 자동 이동하며, "바로 메뉴로 이동" 버튼으로 즉시 이동할 수 있다.
5. 실패 공통: 모달 안에 오류 문구 표시, 장바구니는 유지, "다시 시도" 가능. 재시도 시 같은 `clientOrderId`를 사용한다 (서버가 중복 주문을 만들지 않음).
6. `PRICE_CHANGED`: "메뉴 가격이 변경되었어요." 안내 + "최신 가격으로 갱신" 버튼. 누르면 `details.currentPrices`로 장바구니 단가를 갱신하고 `clientOrderId`를 새로 만든다. 사용자는 갱신된 합계를 확인한 뒤 다시 주문한다.
7. `MENU_UNAVAILABLE`: "판매하지 않는 메뉴가 있어요: {메뉴명}" 안내 + "해당 메뉴 제거" 버튼. 제거 후 남은 항목이 있으면 모달을 닫고 다시 확인하게 한다.
8. `NETWORK_ERROR` / `INTERNAL_ERROR`: "주문을 보내지 못했어요. 잠시 후 다시 시도해주세요."
9. 주문 완료 화면을 새로고침하면 메뉴 화면으로 이동한다 (주문 번호 상태가 없으므로).

## 4. 인증 규칙

### 테이블(고객)
- 앱 시작: 저장된 자격 증명이 없으면 `needs_setup`. 있으면 로그인 호출.
- 로그인 성공: 토큰을 메모리에 보관하고 `authenticated`.
- `INVALID_CREDENTIALS`: 자격 증명을 삭제하지 않고 설정 화면으로 이동하며 "로그인 정보가 맞지 않아요. 관리자에게 문의해주세요."와 함께 매장/테이블 번호는 미리 채운다 (비밀번호는 비움).
- `NETWORK_ERROR`/`INTERNAL_ERROR`: `error` 상태에서 5초마다 자동 재시도하고 "다시 시도" 버튼도 제공한다.
- API 호출 중 `UNAUTHORIZED`(토큰 만료): 저장된 자격 증명으로 1회 재로그인 후 원래 요청을 1회 재시도한다. 재로그인이 실패하면 `needs_setup`.
- 설정 화면에서 초기 설정 성공 시에만 자격 증명을 저장한다.

### 관리자
- 로그인 성공 -> `{accessToken, expiresAt}` 저장 -> `returnTo`(보호 경로로 접근했던 곳) 또는 대시보드로 이동.
- 앱 시작: 저장된 `expiresAt`이 지났으면 삭제하고 로그인 화면. 유효하면 인증 상태 복원.
- 만료 시각에 `setTimeout`으로 자동 로그아웃한다 (타이머는 큰 지연을 안전하게 처리하도록 최대 간격으로 나누어 재설정).
- 어떤 관리자 API든 `UNAUTHORIZED`를 받으면 토큰 삭제 -> 로그인 화면으로 이동하고 "로그인이 만료되었어요. 다시 로그인해주세요." 표시. 현재 경로를 `returnTo`로 보관한다 (US-E9).
- `ACCOUNT_LOCKED`: "로그인 시도가 너무 많아요. {분}분 {초}초 후 다시 시도해주세요." 로그인 버튼을 `retryAfterSeconds` 동안 비활성화하고 매초 카운트다운 표시. 0이 되면 활성화 (US-E4).
- `INVALID_CREDENTIALS`: "매장 식별자, 사용자명 또는 비밀번호가 맞지 않아요." (어느 항목이 틀렸는지는 알리지 않음)
- 로그아웃: 토큰 삭제, SSE 연결 종료, 쿼리 캐시 비우기.

## 5. 주문 상태 변경 규칙 (관리자)

| 현재 상태 | 표시되는 버튼 | 요청 상태 |
|---|---|---|
| 대기중 (`PENDING`) | 준비 시작 | `PREPARING` |
| 준비중 (`PREPARING`) | 완료 처리 | `COMPLETED` |
| 완료 (`COMPLETED`) | 없음 | - |

- 요청 중에는 해당 버튼 비활성화. 성공하면 목록 갱신.
- `INVALID_TRANSITION`(다른 곳에서 먼저 바뀐 경우 등): "이미 상태가 변경되었어요. 최신 상태로 갱신했어요." 표시 후 해당 주문을 다시 조회한다.
- 완료된 주문도 삭제는 가능하다 (직권 수정, US-A3.2).

## 6. 확인 팝업과 피드백 규칙

| 동작 | 팝업 문구 | 성공 피드백 | 실패 피드백 |
|---|---|---|---|
| 주문 삭제 | "주문 {번호}를 삭제할까요? 삭제하면 테이블 총 주문액이 다시 계산돼요." | 토스트 "주문을 삭제했어요." | 토스트 "주문을 삭제하지 못했어요. 다시 시도해주세요." (데이터 변경 없음) |
| 이용 완료 | "테이블 {N}의 이용을 완료할까요? 현재 주문은 과거 내역으로 이동하고 합계가 0원이 돼요." | 토스트 "테이블 {N} 이용을 완료했어요." | `NO_ACTIVE_SESSION`: "이미 이용 완료된 테이블이에요." 후 갱신 / 그 외: "이용 완료 처리에 실패했어요." |
| 메뉴 삭제 | "'{메뉴명}'을(를) 삭제할까요?" | 토스트 "메뉴를 삭제했어요." | 토스트 "메뉴를 삭제하지 못했어요." |
| 테이블 등록 | (팝업 없음) | 토스트 "테이블 {N}을(를) 등록했어요." | `DUPLICATE_TABLE`: "이미 등록된 테이블 번호예요." |

- 팝업은 "확인"/"취소" 두 버튼. Esc 또는 배경 클릭으로 취소. 처리 중에는 확인 버튼 비활성화.
- 토스트는 3초 후 사라지며 오류 토스트는 5초 표시.

## 7. 실시간/폴링 규칙

### 고객 주문 내역 (폴링)
- "주문 내역" 화면이 열려 있고 브라우저 탭이 보일 때만 5초마다 갱신한다 (백그라운드 탭에서는 중지).
- 무한 스크롤: 처음 10건, 목록 끝 근처(sentinel)가 보이면 다음 10건을 불러온다. 폴링은 이미 불러온 페이지를 모두 다시 조회한다.
- 정렬은 최신 주문이 위. 현재 세션 주문만 표시된다 (서버가 보장).
- 폴링 실패: 이전 데이터를 유지하고 작은 안내 "연결이 불안정해요. 다시 불러오는 중..."을 표시한다. 다음 주기에 성공하면 안내를 지운다 (US-E6).
- 세션 종료로 목록이 비면 "주문 내역이 없어요" 빈 화면 표시.

### 관리자 대시보드 (SSE)
- 로그인된 관리자 영역에서 `/api/admin/events` 스트림을 연결한다 (Authorization 헤더 사용).
- 이벤트 수신 시 `dashboard` 쿼리를 무효화하여 재조회한다. `order_status_changed`, `order_deleted`, `session_ended`, `menu_changed`도 동일하게 처리하고, 열려 있는 주문 상세/과거 내역 쿼리도 관련 이벤트에 맞춰 무효화한다.
- 연결 끊김: 상태를 `reconnecting`으로 바꾸고 1초, 2초, 4초, 8초, 이후 10초 간격으로 재연결한다. 재연결 성공 시 대시보드를 즉시 재조회한다.
- 화면 상단에 연결 상태 표시: 연결됨(초록 점) / 재연결 중(주황 점 + "실시간 연결이 끊겨 다시 연결하는 중이에요").
- 재연결이 계속 실패하는 동안에도 수동 새로고침 버튼으로 재조회할 수 있다.

### 신규 주문 강조 (Q8: B)
- `order_created` 이벤트를 받으면 해당 테이블의 `UnseenOrders`에 주문 ID를 추가한다. 이벤트 이후 재조회로 주문 정보가 도착하면 카드가 강조(배경색 + 펄스 애니메이션)된다.
- 강조는 관리자가 그 테이블의 카드 헤더 또는 주문 행을 클릭할 때 해제된다 (테이블 단위).
- `UnseenOrders`는 메모리에만 있으며 새로고침하면 사라진다. 이미 존재하던 주문은 강조하지 않는다.
- 새 주문이 오면 강조된 카드가 있어도 계속 강조 상태를 유지한다 (해제 전까지 누적).

## 8. 표시 규칙

| 항목 | 규칙 |
|---|---|
| 금액 | `12,000원` (천 단위 구분 + "원"). 0은 `0원` |
| 날짜/시간 | `YYYY-MM-DD HH:mm` (브라우저 로컬 시간) |
| 메뉴 요약 | 첫 메뉴명 + `외 N건` (예: `김치찌개 외 2건`, 항목이 1개면 메뉴명만) |
| 상태 배지 | 대기중(노랑), 준비중(파랑), 완료(초록) - 색뿐 아니라 텍스트도 함께 표시 |
| 터치 대상 | 모든 버튼/탭/입력 최소 44x44px |
| 이미지 | `imageUrl`이 없거나 로드 실패 시 회색 대체 영역 + 메뉴명 첫 글자 표시 |
| 빈 상태 | 메뉴 없음 "등록된 메뉴가 없어요", 주문 없음 "주문 내역이 없어요", 테이블 없음 "등록된 테이블이 없어요" |
| 로딩 | 데이터 최초 로딩은 스켈레톤/스피너, 갱신 중에는 기존 데이터를 유지 |
| 접근성 | 버튼에 텍스트 또는 `aria-label`, 팝업은 포커스 트랩 + Esc 닫기, 오류는 `role="alert"`, 상태는 색 외에 텍스트 병기 |

## 9. 메뉴 관리 규칙 (관리자)

- 목록은 카테고리별로 묶어 표시하고, 각 행에 수정/삭제/위로/아래로 버튼을 둔다.
- 위/아래 이동은 같은 카테고리 내에서만 가능하다. 첫 항목의 "위로", 마지막 항목의 "아래로"는 비활성. 클릭하면 해당 카테고리의 전체 ID 순서를 재계산해 `reorder` 요청을 보낸다. 요청 중에는 이동 버튼을 비활성화한다.
- 등록/수정은 모달 폼. 저장 성공 시 모달을 닫고 목록을 갱신한다. `VALIDATION_ERROR`는 필드별로 표시한다 (US-E7).
- 카테고리 입력은 기존 카테고리를 자동완성 후보로 제안한다 (자유 입력 허용).
- 카테고리 순서는 서버가 반환한 순서를 따른다. 새 카테고리는 맨 뒤.

## 10. 테이블 관리 규칙 (관리자)

- 테이블 목록: 번호, 세션 상태(이용 중/비어 있음). 번호 오름차순.
- 등록 폼: 테이블 번호 + 비밀번호(숫자 4자리). 등록 후 태블릿에서 `/customer/setup`에서 같은 값으로 초기 설정한다는 안내 문구를 표시한다.
- 이용 완료/과거 내역 버튼은 대시보드 카드에 있다. 테이블 관리 화면에서도 같은 컴포넌트를 재사용한다.
- 과거 내역: 모달. 시작일/종료일 필터(G5), 시간 역순 목록, "닫기" 버튼으로 대시보드 복귀. 필터를 바꾸면 즉시 재조회한다.

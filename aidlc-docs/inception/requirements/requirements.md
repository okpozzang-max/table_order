## 3. 시스템 구성

- 고객용 웹UI: 테이블 태블릿 브라우저에서 동작하는 주문 화면 (React)
- 관리자용 웹UI: 매장 운영자용 관리 화면 (React)
- 백엔드 API 서버: 주문 처리, 인증, 실시간(SSE) 이벤트 제공 (FastAPI)
- 데이터 저장소: 메뉴, 테이블, 테이블 세션, 주문, 주문 이력 저장 (SQLite)

## 4. 기능 요구사항

### 4.1 고객용 (Customer)

**FR-C1. 테이블 태블릿 자동 로그인 및 세션 관리**
- FR-C1.1 초기 설정(관리자가 1회 수행): 매장 식별자, 테이블 번호, 테이블 비밀번호 입력 후 로그인 정보를 브라우저 로컬에 저장
- FR-C1.2 1회 로그인 성공 후, 저장된 정보로 자동 로그인
- FR-C1.3 테이블 인증 실패 시 오류 표시

**FR-C2. 메뉴 조회 및 탐색**
- FR-C2.1 메뉴 화면이 기본 화면으로 항상 표시
- FR-C2.2 카테고리별 메뉴 분류/표시, 카테고리 간 빠른 이동
- FR-C2.3 메뉴 상세: 메뉴명, 가격, 설명, 이미지(URL)
- FR-C2.4 UI: 카드 레이아웃, 터치 친화적 버튼(최소 44x44px), 명확한 시각적 계층
- FR-C2.5 노출 순서 설정에 따라 정렬

**FR-C3. 장바구니 관리**
- FR-C3.1 메뉴 추가/삭제, 수량 증가/감소, 총 금액 실시간 계산, 장바구니 비우기
- FR-C3.2 클라이언트 로컬 저장으로 새로고침 시에도 유지
- FR-C3.3 서버 전송은 주문 확정 시에만 수행

**FR-C4. 주문 생성**
- FR-C4.1 주문 내역 최종 확인 후 주문 확정
- FR-C4.2 성공 시: 주문 번호 표시 -> 장바구니 자동 비우기 -> 5초 표시 후 메뉴 화면으로 자동 리다이렉트
- FR-C4.3 실패 시: 에러 메시지 표시, 장바구니 유지
- FR-C4.4 주문 정보: 매장 식별 정보, 테이블 식별 정보, 메뉴 목록(메뉴명/수량/단가), 총 금액, 세션 ID
- FR-C4.5 서버는 클라이언트가 보낸 금액을 신뢰하지 않고 서버 저장 메뉴 가격으로 총 금액을 재계산해 검증

**FR-C5. 주문 내역 조회**
- FR-C5.1 현재 테이블 세션의 주문만 표시 (이전 세션, 이용 완료 처리된 주문 제외)
- FR-C5.2 주문 시간 순 정렬, 주문별 상세(주문 번호, 시각, 메뉴/수량, 금액, 상태 대기중/준비중/완료)
- FR-C5.3 페이지네이션 또는 무한 스크롤
- FR-C5.4 상태는 5~10초 주기 폴링으로 갱신

### 4.2 관리자용 (Admin)

**FR-A1. 매장 인증**
- FR-A1.1 매장 식별자, 사용자명, 비밀번호로 로그인 (관리자 계정은 환경설정으로 지정된 1개)
- FR-A1.2 JWT 기반 인증, 16시간 세션 유지, 브라우저 새로고침 시 세션 유지, 16시간 후 자동 로그아웃
- FR-A1.3 비밀번호는 bcrypt 해싱으로 저장/비교
- FR-A1.4 연속 5회 로그인 실패 시 15분 잠금

**FR-A2. 실시간 주문 모니터링**
- FR-A2.1 Server-Sent Events(SSE)로 주문 목록 실시간 업데이트, 주문 발생 후 2초 이내 화면 표시
- FR-A2.2 테이블별 카드 그리드 대시보드: 테이블 총 주문액, 최신 주문 n개 미리보기
- FR-A2.3 주문 상세: 테이블 번호, 주문 번호, 주문 시각, 메뉴/수량(축약), 총 금액. 카드 클릭 시 전체 메뉴 목록 상세
- FR-A2.4 주문 상태 변경: 대기중 → 준비중 → 완료 순차 전이만 허용
- FR-A2.5 신규 주문 시각적 강조 (색상 변경/애니메이션)
- FR-A2.6 테이블별 필터링

**FR-A3. 테이블 관리**
- FR-A3.1 테이블 태블릿 초기 설정: 테이블 번호/비밀번호 설정, 설정 저장 및 자동 로그인 활성화 (16시간 세션)
- FR-A3.2 주문 삭제(직권 수정): 삭제 버튼 -> 확인 팝업 -> 즉시 삭제 -> 테이블 총 주문액 재계산 -> 성공/실패 피드백
- FR-A3.3 테이블 세션: 세션의 첫 주문 시 시작, 관리자의 "이용 완료" 처리로 종료. 확인 팝업, 성공/실패 피드백
- FR-A3.4 세션 종료 시 해당 세션 주문을 과거 이력(OrderHistory)으로 이동, 현재 주문 목록/총 주문액 0으로 리셋, 다음 고객은 이전 내역 없이 시작
- FR-A3.5 과거 주문 내역 조회: "과거 내역" 버튼, 테이블별 시간 역순 목록(주문 번호, 시각, 메뉴 목록, 총 금액, 이용 완료 시각), 날짜 필터, "닫기"로 대시보드 복귀
- FR-A3.6 세션 ID로 주문 그룹화, 완료 시각 기록

**FR-A4. 메뉴 관리**
- FR-A4.1 카테고리별 메뉴 조회
- FR-A4.2 메뉴 등록: 메뉴명, 가격, 설명, 카테고리(문자열), 이미지 URL
- FR-A4.3 메뉴 수정, 삭제, 노출 순서 조정
- FR-A4.4 데이터 검증: 필수 필드, 가격 범위

## 6. 범위 제외 (constraints.md 반영)

- 결제(실결제, PG 연동, 영수증, 환불, 포인트/쿠폰)
- 복잡한 인증(OAuth/SNS 로그인, 2FA/OTP)
- 이미지 리사이징/최적화, 컨텐츠 관리, 광고
- 푸시/SMS/이메일/소리·진동 알림
- 주문 내역의 주방 전달, 식재료 재고 관리
- 데이터 분석/대시보드, 매출 리포트, 재고, 직원 관리/권한, 예약, 리뷰, 다국어
- 배달 플랫폼/POS/소셜 공유/지도/번역 API 연동
- 본 질문 답변으로 추가 제외: 멀티 매장, 관리자 회원가입, 이미지 업로드, 카테고리 CRUD, AWS 배포, Docker

## 7. 사용자 시나리오 (요약)

1. 관리자가 테이블 태블릿에 매장/테이블 정보를 1회 입력해 자동 로그인을 설정한다.
2. 고객이 메뉴를 탐색해 장바구니에 담고 주문을 확정한다 (첫 주문 시 테이블 세션 시작).
3. 관리자 대시보드에 SSE로 주문이 2초 이내 표시되고, 관리자가 상태를 대기중 → 준비중 → 완료로 변경한다.
4. 고객 주문 내역 화면은 5~10초 폴링으로 상태를 갱신한다.
5. 관리자가 필요 시 주문을 삭제하고, 식사가 끝나면 이용 완료 처리해 세션을 종료한다 (주문 -> 과거 이력, 현재 합계 0).
6. 관리자가 과거 내역을 날짜 필터로 조회한다.
7. 관리자가 메뉴를 등록/수정/삭제하고 노출 순서를 조정한다.

## 8. 오류/엣지 케이스

- 주문 실패(네트워크/검증 오류): 에러 메시지, 장바구니 유지
- 존재하지 않거나 삭제된 메뉴가 장바구니에 있는 경우: 주문 시 서버 검증 후 오류 안내
- 이미 종료된 세션/잘못된 상태 전이(예: 완료 -> 준비중) 요청: 거부 및 오류 응답
- 로그인 잠금 중 시도: 잠금 안내와 남은 시간 표시
- SSE 연결 끊김: 클라이언트 자동 재연결

## 9. 성공 기준

- 위 MVP 범위(고객 FR-C1~C5, 관리자 FR-A1~A4)가 로컬 환경에서 동작한다.
- 관리자 화면에 신규 주문이 2초 이내 표시된다.
- 세션 종료 후 고객 주문 내역이 비워지고, 관리자 과거 내역에서 해당 주문을 조회할 수 있다.

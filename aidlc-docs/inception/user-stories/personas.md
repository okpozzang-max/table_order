# 페르소나 (Personas)

요구사항: `aidlc-docs/inception/requirements/requirements.md`
정의 방식: 2개 페르소나 (Story Plan Q5: A)

---

## P1. 테이블 고객 (Table Customer)

| 항목 | 내용 |
|---|---|
| 역할 | 매장 테이블에서 식사하며 태블릿으로 주문하는 이용자 |
| 대표 인물 | 민지 (20~40대, 2~4인 동반) |
| 사용 환경 | 테이블에 고정된 태블릿의 웹 브라우저. 한국어 UI, 터치 입력 |
| 기술 숙련도 | 낮음~중간. 별도 설명 없이 바로 사용할 수 있어야 함 |
| 사용 패턴 | 짧은 시간 동안 여러 번 (최초 주문, 추가 주문, 상태 확인) |

**목표**
- 직원을 기다리지 않고 즉시 주문한다.
- 메뉴 정보(가격, 설명, 이미지)를 보고 쉽게 고른다.
- 주문한 내역과 처리 상태를 확인한다.

**불편 사항 (Pain Points)**
- 직원 호출을 위한 대기 시간
- 로그인이나 복잡한 입력 절차
- 주문이 제대로 들어갔는지 알 수 없는 불안감
- 이전 손님의 주문 내역이 보이는 혼란

**관련 요구사항**: FR-C1 ~ FR-C5

---

## P2. 매장 관리자 (Store Admin)

| 항목 | 내용 |
|---|---|
| 역할 | 매장을 운영하며 주문, 테이블, 메뉴를 관리하는 운영자 (매장당 1개 계정) |
| 대표 인물 | 정훈 (30~50대, 매장 점주 또는 매니저) |
| 사용 환경 | 카운터 PC/태블릿의 웹 브라우저. 한국어 UI. 영업시간 내내 화면을 켜둠 |
| 기술 숙련도 | 중간. 직관적인 관리 도구를 기대함 |
| 계정 | 환경설정으로 지정된 단일 계정 (회원가입 없음) |

**목표**
- 들어오는 주문을 놓치지 않고 실시간으로 확인한다.
- 주문 상태를 관리하고, 필요하면 직권으로 주문을 수정(삭제)한다.
- 손님이 식사를 마치면 테이블을 깔끔하게 초기화한다.
- 태블릿 초기 설정과 메뉴 변경을 직접 처리한다.

**불편 사항 (Pain Points)**
- 주문 누락이나 전달 지연
- 테이블별 현재 주문과 합계를 한눈에 파악하기 어려움
- 이전 손님 주문과 현재 주문이 섞이는 문제
- 메뉴 변경을 위해 개발자 도움이 필요한 상황

**관련 요구사항**: FR-A1 ~ FR-A4

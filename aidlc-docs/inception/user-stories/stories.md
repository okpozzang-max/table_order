# 사용자 스토리 (User Stories)

- 요구사항: `aidlc-docs/inception/requirements/requirements.md`
- 페르소나: `aidlc-docs/inception/user-stories/personas.md`
- 구성: 페르소나 > 기능 에픽 > 스토리 (Plan Q1: A)
- 스토리 형식: "[페르소나]로서 ... 원한다. 그래야 ..." (Q2: A)
- 인수 조건: Given / When / Then (Q3: A)
- 우선순위: 표기하지 않음, 전부 MVP 필수 (Q6: A)
- 오류/예외: 별도 에픽 EP-E로 분리 (Q7: B)
- 추적성: 각 스토리에 요구사항 ID 명시 (Q8: A)

스토리 수: 정상 흐름 25개 (고객 10 + 관리자 15) + 오류/예외 9개 = 총 34개

# 고객 (P1. 테이블 고객)

## EP-C1. 테이블 자동 로그인

### US-C1.1 저장된 정보로 자동 로그인
- **스토리**: 테이블 고객으로서, 태블릿을 켜면 별도 로그인 없이 바로 메뉴 화면이 보이길 원한다. 그래야 대기 없이 즉시 주문할 수 있다.
- **요구사항**: FR-C1.1, FR-C1.2
- **인수 조건**:
  - Given 관리자가 매장 식별자, 테이블 번호, 비밀번호로 초기 설정을 1회 완료했고 로그인 정보가 브라우저에 저장되어 있다, When 고객 화면을 열거나 새로고침한다, Then 로그인 입력 없이 자동으로 인증되어 메뉴 화면이 표시된다.
  - Given 자동 로그인에 성공했다, When 화면이 표시된다, Then 기본 화면은 항상 메뉴 화면이다.

## EP-C2. 메뉴 조회 및 탐색

### US-C2.1 카테고리별 메뉴 탐색
- **스토리**: 테이블 고객으로서, 카테고리별로 나뉜 메뉴를 빠르게 오가며 보고 싶다. 그래야 원하는 메뉴를 쉽게 찾을 수 있다.
- **요구사항**: FR-C2.1, FR-C2.2, FR-C2.5
- **인수 조건**:
  - Given 메뉴가 여러 카테고리로 등록되어 있다, When 메뉴 화면을 연다, Then 카테고리별로 분류된 메뉴가 관리자가 정한 노출 순서대로 표시된다.
  - Given 메뉴 화면이 표시되어 있다, When 다른 카테고리를 선택한다, Then 해당 카테고리의 메뉴로 즉시 이동한다.

### US-C2.2 메뉴 상세 정보 확인
- **스토리**: 테이블 고객으로서, 메뉴의 이름, 가격, 설명, 이미지를 카드 형태로 보고 싶다. 그래야 내용을 확인하고 고를 수 있다.
- **요구사항**: FR-C2.3, FR-C2.4
- **인수 조건**:
  - Given 메뉴가 등록되어 있다, When 메뉴 카드가 표시된다, Then 메뉴명, 가격, 설명, 이미지(URL)가 보인다.
  - Given 터치 화면에서 사용한다, When 버튼을 누른다, Then 모든 터치 대상은 최소 44x44px 크기이다.

## EP-C3. 장바구니 관리

### US-C3.1 장바구니에 메뉴 담기와 삭제
- **스토리**: 테이블 고객으로서, 메뉴를 장바구니에 담고 뺄 수 있길 원한다. 그래야 주문 전에 고른 것을 정리할 수 있다.
- **요구사항**: FR-C3.1
- **인수 조건**:
  - Given 메뉴 카드가 표시되어 있다, When 담기 버튼을 누른다, Then 해당 메뉴가 장바구니에 추가된다.
  - Given 장바구니에 메뉴가 있다, When 해당 항목을 삭제한다, Then 장바구니에서 제거된다.

### US-C3.2 수량 조절과 총 금액 확인
- **스토리**: 테이블 고객으로서, 수량을 늘리고 줄이며 총 금액을 바로 보고 싶다. 그래야 주문 금액을 예상할 수 있다.
- **요구사항**: FR-C3.1
- **인수 조건**:
  - Given 장바구니에 메뉴가 있다, When 수량을 증가 또는 감소시킨다, Then 항목 수량과 총 금액이 즉시 다시 계산되어 표시된다.
  - Given 수량이 1이다, When 감소시킨다, Then 해당 항목이 장바구니에서 제거된다.

### US-C3.3 장바구니 유지와 비우기
- **스토리**: 테이블 고객으로서, 화면을 새로고침해도 장바구니가 유지되고 필요하면 한 번에 비우고 싶다. 그래야 실수로 내용을 잃지 않고 다시 시작할 수도 있다.
- **요구사항**: FR-C3.1, FR-C3.2, FR-C3.3
- **인수 조건**:
  - Given 장바구니에 항목이 있다, When 페이지를 새로고침한다, Then 장바구니 내용이 그대로 유지된다. (클라이언트 로컬 저장)
  - Given 장바구니에 항목이 있다, When 비우기를 실행한다, Then 장바구니가 비워지고 총 금액이 0이 된다.
  - Given 장바구니를 편집 중이다, When 주문을 확정하기 전이다, Then 서버로는 아무 데이터도 전송되지 않는다.

## EP-C4. 주문 생성

### US-C4.1 주문 내용 확인 후 확정
- **스토리**: 테이블 고객으로서, 주문 내용을 최종 확인한 뒤 확정하고 싶다. 그래야 잘못된 주문을 막을 수 있다.
- **요구사항**: FR-C4.1, FR-C4.4, FR-C4.5
- **인수 조건**:
  - Given 장바구니에 항목이 있다, When 주문하기를 누른다, Then 메뉴, 수량, 총 금액을 보여주는 최종 확인 화면이 표시된다.
  - Given 최종 확인 화면이다, When 주문 확정을 누른다, Then 매장, 테이블, 메뉴 목록(메뉴명/수량/단가), 총 금액, 세션 ID를 포함한 주문이 서버로 전송된다.
  - Given 주문이 전송되었다, When 서버가 처리한다, Then 서버는 저장된 메뉴 가격으로 총 금액을 다시 계산해 검증한다.

### US-C4.2 주문 성공 확인과 메뉴 화면 복귀
- **스토리**: 테이블 고객으로서, 주문이 성공하면 주문 번호를 보고 자동으로 메뉴 화면으로 돌아가길 원한다. 그래야 주문이 접수됐음을 확신하고 계속 이용할 수 있다.
- **요구사항**: FR-C4.2
- **인수 조건**:
  - Given 주문이 성공했다, When 결과가 표시된다, Then 주문 번호가 화면에 보이고 장바구니가 자동으로 비워진다.
  - Given 주문 번호가 표시되었다, When 5초가 지난다, Then 메뉴 화면으로 자동 이동한다.

## EP-C5. 주문 내역 조회

### US-C5.1 현재 세션 주문 내역 조회
- **스토리**: 테이블 고객으로서, 우리 테이블의 이번 식사 주문 내역을 보고 싶다. 그래야 무엇을 얼마나 주문했는지 확인할 수 있다.
- **요구사항**: FR-C5.1, FR-C5.2, FR-C5.3
- **인수 조건**:
  - Given 현재 테이블 세션에 주문이 있다, When 주문 내역 화면을 연다, Then 주문 번호, 주문 시각, 메뉴와 수량, 금액, 상태(대기중/준비중/완료)가 주문 시간 순으로 표시된다.
  - Given 이전 세션의 주문이나 이용 완료 처리된 주문이 있다, When 주문 내역을 조회한다, Then 해당 주문은 표시되지 않는다.
  - Given 주문이 많다, When 목록을 본다, Then 페이지네이션 또는 무한 스크롤로 나누어 표시된다.

### US-C5.2 주문 상태 자동 갱신
- **스토리**: 테이블 고객으로서, 주문 상태가 바뀌면 화면에 자동으로 반영되길 원한다. 그래야 새로고침 없이 진행 상황을 알 수 있다.
- **요구사항**: FR-C5.4
- **인수 조건**:
  - Given 주문 내역 화면이 열려 있다, When 관리자가 주문 상태를 변경한다, Then 화면은 5~10초 주기의 폴링으로 새 상태를 반영한다.

# 관리자 (P2. 매장 관리자)

## EP-A1. 매장 인증

### US-A1.1 매장 로그인
- **스토리**: 매장 관리자로서, 매장 식별자, 사용자명, 비밀번호로 로그인하고 싶다. 그래야 내 매장의 관리 기능에만 접근할 수 있다.
- **요구사항**: FR-A1.1, FR-A1.3
- **인수 조건**:
  - Given 환경설정에 관리자 계정이 지정되어 있다, When 올바른 매장 식별자, 사용자명, 비밀번호를 입력한다, Then 로그인에 성공하고 JWT 토큰이 발급된다.
  - Given 비밀번호를 저장해야 한다, When 계정 정보를 처리한다, Then 비밀번호는 bcrypt 해시로만 비교/보관되며 평문으로 저장되지 않는다.

### US-A1.2 16시간 세션 유지
- **스토리**: 매장 관리자로서, 한 번 로그인하면 영업 중 계속 로그인 상태가 유지되길 원한다. 그래야 새로고침하거나 오래 써도 다시 로그인하지 않는다.
- **요구사항**: FR-A1.2
- **인수 조건**:
  - Given 로그인한 지 16시간 이내다, When 브라우저를 새로고침한다, Then 로그인 상태가 유지된다.
  - Given 로그인한 지 16시간이 지났다, When 다음 요청을 보내거나 화면이 갱신된다, Then 자동으로 로그아웃되고 로그인 화면으로 이동한다.

## EP-A2. 실시간 주문 모니터링

### US-A2.1 테이블별 주문 대시보드 확인
- **스토리**: 매장 관리자로서, 테이블별 카드로 총 주문액과 최근 주문을 한눈에 보고 싶다. 그래야 매장 상황을 빠르게 파악할 수 있다.
- **요구사항**: FR-A2.2
- **인수 조건**:
  - Given 로그인했다, When 대시보드를 연다, Then 테이블별 카드가 그리드로 표시되고 각 카드에 현재 세션의 총 주문액과 최신 주문 n개 미리보기가 보인다.
  - Given 주문이 없는 테이블이다, When 대시보드를 본다, Then 총 주문액은 0으로 표시된다.

### US-A2.2 신규 주문 실시간 수신과 강조
- **스토리**: 매장 관리자로서, 새 주문이 들어오면 새로고침 없이 바로 눈에 띄게 보고 싶다. 그래야 주문을 놓치지 않는다.
- **요구사항**: FR-A2.1, FR-A2.5
- **인수 조건**:
  - Given 대시보드가 열려 있다, When 고객이 주문을 확정한다, Then SSE로 전달되어 2초 이내에 해당 테이블 카드에 반영된다.
  - Given 신규 주문이 도착했다, When 카드가 갱신된다, Then 색상 변경이나 애니메이션으로 시각적으로 강조된다.

### US-A2.3 주문 상세 보기
- **스토리**: 매장 관리자로서, 주문 카드를 눌러 전체 메뉴 목록을 보고 싶다. 그래야 축약되지 않은 상세 내용을 확인할 수 있다.
- **요구사항**: FR-A2.3
- **인수 조건**:
  - Given 대시보드에 주문이 표시되어 있다, When 주문 카드를 클릭한다, Then 테이블 번호, 주문 번호, 주문 시각, 전체 메뉴와 수량, 총 금액이 표시된다.

### US-A2.4 주문 상태 변경
- **스토리**: 매장 관리자로서, 주문 상태를 대기중, 준비중, 완료로 바꾸고 싶다. 그래야 진행 상황을 고객과 공유할 수 있다.
- **요구사항**: FR-A2.4
- **인수 조건**:
  - Given 주문 상태가 대기중이다, When 상태를 변경한다, Then 준비중으로만 변경할 수 있다.
  - Given 주문 상태가 준비중이다, When 상태를 변경한다, Then 완료로만 변경할 수 있다.
  - Given 상태가 변경되었다, When 저장된다, Then 대시보드에 반영되고 고객 주문 내역에도 폴링 주기 안에 반영된다.

### US-A2.5 테이블별 필터링
- **스토리**: 매장 관리자로서, 특정 테이블의 주문만 골라 보고 싶다. 그래야 해당 테이블에 집중할 수 있다.
- **요구사항**: FR-A2.6
- **인수 조건**:
  - Given 대시보드에 여러 테이블이 있다, When 특정 테이블을 필터로 선택한다, Then 해당 테이블의 주문만 표시된다.
  - Given 필터를 적용했다, When 필터를 해제한다, Then 모든 테이블이 다시 표시된다.

## EP-A3. 테이블 관리

### US-A3.1 테이블 태블릿 초기 설정
- **스토리**: 매장 관리자로서, 테이블 번호와 비밀번호를 설정해 태블릿을 등록하고 싶다. 그래야 해당 태블릿이 자동 로그인 상태로 쓰일 수 있다.
- **요구사항**: FR-A3.1, FR-C1.1
- **인수 조건**:
  - Given 로그인한 관리자가 설정 화면에 있다, When 테이블 번호와 비밀번호를 입력해 저장한다, Then 테이블 정보가 저장되고(비밀번호는 평문 저장 금지) 16시간 세션이 생성된다.
  - Given 태블릿에서 매장 식별자, 테이블 번호, 비밀번호를 입력해 인증에 성공했다, When 정보가 저장된다, Then 이후 자동 로그인이 활성화된다.

### US-A3.2 주문 삭제 (직권 수정)
- **스토리**: 매장 관리자로서, 잘못 들어온 주문을 삭제하고 싶다. 그래야 테이블 합계를 정확하게 유지할 수 있다.
- **요구사항**: FR-A3.2
- **인수 조건**:
  - Given 주문이 표시되어 있다, When 삭제 버튼을 누른다, Then 확인 팝업이 표시된다.
  - Given 확인 팝업이 표시되었다, When 삭제를 확인한다, Then 주문이 즉시 삭제되고 해당 테이블의 총 주문액이 다시 계산되며 성공 피드백이 표시된다.

### US-A3.3 테이블 이용 완료 처리 (세션 종료)
- **스토리**: 매장 관리자로서, 손님이 식사를 마치면 테이블을 이용 완료 처리하고 싶다. 그래야 다음 손님이 이전 내역 없이 시작한다.
- **요구사항**: FR-A3.3, FR-A3.4, FR-A3.6
- **인수 조건**:
  - Given 테이블에 세션이 없다, When 고객이 첫 주문을 확정한다, Then 새 테이블 세션이 시작되고 이후 주문은 같은 세션 ID로 그룹화된다.
  - Given 진행 중인 세션이 있다, When 이용 완료를 누른다, Then 확인 팝업이 표시된다.
  - Given 확인 팝업에서 확정했다, When 처리된다, Then 해당 세션의 주문이 과거 이력(OrderHistory)으로 이동하고 완료 시각이 기록되며 현재 주문 목록과 총 주문액이 0으로 리셋되고 성공 피드백이 표시된다.
  - Given 세션이 종료되었다, When 같은 테이블에서 새 고객이 첫 주문을 한다, Then 새로운 세션이 시작되며 고객 주문 내역에는 이전 주문이 보이지 않는다.

### US-A3.4 과거 주문 내역 조회
- **스토리**: 매장 관리자로서, 테이블별 과거 주문 내역을 날짜로 걸러 보고 싶다. 그래야 지난 이용 기록을 확인할 수 있다.
- **요구사항**: FR-A3.5
- **인수 조건**:
  - Given 테이블 카드가 표시되어 있다, When "과거 내역" 버튼을 누른다, Then 해당 테이블의 과거 주문이 시간 역순으로 표시되고 각 항목에 주문 번호, 시각, 메뉴 목록, 총 금액, 이용 완료 시각이 보인다.
  - Given 과거 내역이 표시되어 있다, When 날짜 필터를 적용한다, Then 해당 기간의 내역만 표시된다.
  - Given 과거 내역 화면이다, When "닫기"를 누른다, Then 대시보드로 돌아온다.

## EP-A4. 메뉴 관리

### US-A4.1 메뉴 목록 조회
- **스토리**: 매장 관리자로서, 카테고리별로 등록된 메뉴를 보고 싶다. 그래야 현재 메뉴 구성을 파악할 수 있다.
- **요구사항**: FR-A4.1
- **인수 조건**:
  - Given 메뉴가 등록되어 있다, When 메뉴 관리 화면을 연다, Then 카테고리별로 메뉴 목록이 표시된다.

### US-A4.2 메뉴 등록
- **스토리**: 매장 관리자로서, 새 메뉴를 등록하고 싶다. 그래야 고객이 새 메뉴를 주문할 수 있다.
- **요구사항**: FR-A4.2, FR-A4.4
- **인수 조건**:
  - Given 메뉴 등록 화면이다, When 메뉴명, 가격, 설명, 카테고리(문자열), 이미지 URL을 입력해 저장한다, Then 메뉴가 등록되고 고객 메뉴 화면에 표시된다.
  - Given 필수 필드가 비었거나 가격이 허용 범위를 벗어났다, When 저장한다, Then 저장되지 않고 검증 오류가 표시된다. (US-E7 참조)

### US-A4.3 메뉴 수정과 삭제
- **스토리**: 매장 관리자로서, 메뉴 정보를 고치거나 지우고 싶다. 그래야 가격이나 구성 변경을 바로 반영할 수 있다.
- **요구사항**: FR-A4.3
- **인수 조건**:
  - Given 등록된 메뉴가 있다, When 정보를 수정해 저장한다, Then 변경 내용이 고객 메뉴 화면에 반영된다.
  - Given 등록된 메뉴가 있다, When 삭제를 확인한다, Then 해당 메뉴가 고객 메뉴 화면에서 사라진다.

### US-A4.4 메뉴 노출 순서 조정
- **스토리**: 매장 관리자로서, 메뉴가 보이는 순서를 바꾸고 싶다. 그래야 대표 메뉴를 앞에 보여줄 수 있다.
- **요구사항**: FR-A4.3
- **인수 조건**:
  - Given 같은 카테고리에 여러 메뉴가 있다, When 노출 순서를 변경해 저장한다, Then 고객 메뉴 화면이 변경된 순서로 표시된다.

# 오류/예외 처리 (EP-E)

### US-E1. 주문 실패 시 장바구니 유지
- **스토리**: 테이블 고객으로서, 주문이 실패하면 이유를 알고 장바구니가 그대로이길 원한다. 그래야 다시 시도할 수 있다.
- **요구사항**: FR-C4.3
- **인수 조건**:
  - Given 주문 확정을 눌렀다, When 네트워크 오류나 서버 검증 오류로 실패한다, Then 에러 메시지가 표시되고 장바구니 내용은 그대로 유지된다.
  - Given 주문이 실패했다, When 다시 주문 확정을 누른다, Then 재시도할 수 있고 중복 주문이 생성되지 않는다.

### US-E2. 존재하지 않는 메뉴가 담긴 주문 처리
- **스토리**: 테이블 고객으로서, 그 사이 삭제/변경된 메뉴가 장바구니에 있을 때 안내를 받고 싶다. 그래야 잘못된 가격으로 주문되지 않는다.
- **요구사항**: FR-C4.5, 요구사항 8절
- **인수 조건**:
  - Given 장바구니에 이미 삭제된 메뉴가 있다, When 주문을 확정한다, Then 서버가 주문을 거부하고 어떤 메뉴가 문제인지 안내하며 장바구니는 유지된다.
  - Given 메뉴 가격이 변경되었다, When 주문을 확정한다, Then 서버는 저장된 현재 가격으로 금액을 계산하고, 클라이언트 금액과 다르면 안내한다.

### US-E3. 테이블 로그인 실패 처리
- **스토리**: 테이블 고객 또는 설정 담당 관리자로서, 로그인 정보가 틀리면 명확한 오류를 보고 싶다. 그래야 정보를 고쳐 다시 설정할 수 있다.
- **요구사항**: FR-C1.3
- **인수 조건**:
  - Given 저장된 또는 입력한 테이블 인증 정보가 올바르지 않다, When 인증을 시도한다, Then 오류 메시지가 표시되고 주문 기능은 사용할 수 없다.
  - Given 저장된 정보가 더 이상 유효하지 않다, When 자동 로그인에 실패한다, Then 초기 설정 화면으로 이동한다.

### US-E4. 관리자 로그인 실패와 잠금
- **스토리**: 매장 관리자로서, 로그인 실패가 반복되면 계정이 보호되길 원한다. 그래야 무차별 대입 공격을 막을 수 있다.
- **요구사항**: FR-A1.4
- **인수 조건**:
  - Given 로그인에 연속 4회 실패했다, When 5번째로 또 실패한다, Then 계정은 15분간 잠긴다.
  - Given 계정이 잠겨 있다, When 올바른 정보로 로그인을 시도한다, Then 로그인되지 않고 잠금 안내와 남은 시간이 표시된다.
  - Given 15분이 지났다, When 올바른 정보로 로그인한다, Then 로그인에 성공하고 실패 횟수가 초기화된다.

### US-E5. 잘못된 주문 상태 전이 거부
- **스토리**: 매장 관리자로서, 허용되지 않는 상태 변경은 막히길 원한다. 그래야 상태 흐름이 일관되게 유지된다.
- **요구사항**: FR-A2.4, 요구사항 8절
- **인수 조건**:
  - Given 주문 상태가 완료다, When 준비중이나 대기중으로 변경을 요청한다, Then 서버가 거부하고 오류 메시지가 표시된다.
  - Given 주문 상태가 대기중이다, When 완료로 건너뛰는 변경을 요청한다, Then 서버가 거부한다.

### US-E6. 실시간 갱신 연결 오류 복구
- **스토리**: 사용자(관리자/고객)로서, 연결이 끊겨도 화면이 자동으로 복구되길 원한다. 그래야 수동 새로고침 없이 최신 상태를 본다.
- **요구사항**: FR-A2.1, FR-C5.4, 요구사항 8절
- **인수 조건**:
  - Given 관리자 대시보드의 SSE 연결이 끊겼다, When 일정 시간이 지난다, Then 클라이언트가 자동으로 재연결하고 재연결 후 놓친 변경분을 반영한다.
  - Given 고객 화면의 폴링 요청이 실패했다, When 다음 폴링 주기가 되면, Then 다시 요청하고 성공하면 최신 상태가 표시된다.

### US-E7. 입력 검증 실패 안내 (메뉴 관리)
- **스토리**: 매장 관리자로서, 잘못 입력한 메뉴 정보에 대해 이유를 알려주길 원한다. 그래야 바로 고칠 수 있다.
- **요구사항**: FR-A4.4
- **인수 조건**:
  - Given 메뉴명이나 가격 등 필수 값이 비어 있다, When 저장한다, Then 누락된 필드가 표시되고 저장되지 않는다.
  - Given 가격이 허용 범위를 벗어났다(0 이하 등), When 저장한다, Then 가격 범위 오류가 표시되고 저장되지 않는다.

### US-E8. 삭제/이용 완료 처리 실패 피드백
- **스토리**: 매장 관리자로서, 주문 삭제나 이용 완료 처리가 실패하면 알림을 받고 데이터가 변하지 않길 원한다. 그래야 데이터가 어긋나지 않는다.
- **요구사항**: FR-A3.2, FR-A3.3
- **인수 조건**:
  - Given 주문 삭제 또는 이용 완료 처리를 확정했다, When 서버 오류가 발생한다, Then 실패 메시지가 표시되고 데이터는 처리 이전 상태로 유지된다. (트랜잭션)
  - Given 이미 종료된 세션이나 이미 삭제된 주문에 대한 요청이다, When 처리한다, Then 서버가 거부하고 오류를 안내한다.

### US-E9. 관리자 세션 만료 후 재인증
- **스토리**: 매장 관리자로서, 세션이 만료되면 명확히 안내받고 다시 로그인하고 싶다. 그래야 만료된 상태로 작업하다 실패하지 않는다.
- **요구사항**: FR-A1.2
- **인수 조건**:
  - Given JWT 토큰이 만료되었거나 유효하지 않다, When 관리자 API를 호출한다, Then 인증 오류(401)가 반환되고 로그인 화면으로 이동한다.
  - Given 재로그인에 성공했다, When 이동한다, Then 이전에 보던 화면으로 돌아오거나 대시보드가 표시된다.
